# اجرای Claude Code روی یک کامپیوتر قدیمی بدون AVX و AVX2

یک کامپیوتر با پردازندهٔ Intel Core 2 Duo E8400، چهار گیگابایت رم و بدون پشتیبانی از AVX و AVX2 دارم.

روی چنین سیستمی، اجرای بعضی نرم‌افزارهای جدید به یک مسئلهٔ فنی تبدیل می‌شود. Claude Code هم یکی از همین موارد بود. نسخهٔ رسمی مبتنی بر Bun روی این پردازنده اجرا نمی‌شد و برنامه در همان ابتدای کار از کار می‌افتاد.

به‌جای کنار گذاشتن سیستم، تصمیم گرفتم یک سؤال مشخص را آزمایش کنم:

**آیا می‌توان Claude Code را به شکلی اجرا کرد که به قابلیت‌های AVX و AVX2 وابسته نباشد؟**

نتیجهٔ این آزمایش را در قالب یک پروژهٔ مستقل در GitHub منتشر کردم.

## سخت‌افزار و محیط آزمایش

محیط آزمایش عمداً یک سیستم قدیمی است:

- پردازنده: Intel Core 2 Duo E8400
- سیستم‌عامل: Windows 10 Pro x64
- حافظهٔ رم: ۴ گیگابایت
- پشتیبانی از AVX و AVX2: ندارد
- Node.js: نسخهٔ ۲۴.۱۹.۰

این جزئیات مهم‌اند، چون نتیجهٔ این آزمایش را نباید به همهٔ سیستم‌های بدون AVX تعمیم داد. آنچه این پروژه نشان می‌دهد، رفتار همین پیکربندی آزمایش‌شده است.

## راه‌حل چه بود؟

مسیر آزمایش من استفاده از `cc2js` بود.

ایده این است که نسخهٔ Bun-compiled Claude Code را به یک bundle قابل اجرای Node.js تبدیل کنیم.

در این پروژه از نسخه‌های زیر استفاده شد:

- Claude Code `2.1.270`
- `cc2js` `1.2.3`
- Node.js `24.19.0`

تبدیل با موفقیت انجام شد و bundle مربوط به Node.js ساخته شد.

اما صرفاً ساخته‌شدن فایل کافی نبود. چند تست پایه هم انجام دادم:

```text
node cli.js --help
node cli.js mcp --help
node cli.js doctor
```

اجرای CLI و این تست‌ها موفق بود.

یک تست مستقل MCP با transport نوع `stdio` هم انجام شد و ارتباط MCP در این سطح تأیید شد.

بنابراین در محدودهٔ همین آزمایش می‌توان گفت:

**اجرای bundle سازگار با Node.js روی این سیستم و ارتباط پایهٔ MCP تأیید شد.**

## بعد از Claude Code، سراغ Obsidian رفتم

بخش دوم پروژه مربوط به Obsidian بود.

اینجا یک مرز مهم وجود دارد که باید روشن بماند:

**من اتصال کامل Claude Code به Obsidian را در این نسخه تأیید نکرده‌ام.**

در عوض، مسیر Obsidian را به‌صورت مستقل آزمایش کردم.

معماری تست‌شده:

```text
Claude Desktop / MCP Client
        ↓
MCPB
        ↓
Node.js
        ↓
obsidian-mcp-rest 0.1.1
        ↓
HTTPS 127.0.0.1:27124
        ↓
Obsidian Local REST API
        ↓
Obsidian Vault
```

در این مسیر چند عملیات با موفقیت آزمایش شدند:

- کشف Vault
- خواندن یک Note
- جست‌وجو در محتوای Vault
- خواندن JSON یک Note

پس بخش REST و MCP مربوط به Obsidian، در محدودهٔ تست‌های انجام‌شده، قابل استفاده بود.

## یک نکتهٔ فنی دربارهٔ HTTPS

در جریان بررسی پروژه، یک ابهام دربارهٔ endpoint مربوط به Obsidian به وجود آمد.

برای همین، به‌جای حدس‌زدن، کد bridge مورد استفاده را مستقیماً بررسی کردم.

نسخهٔ `obsidian-mcp-rest` که در این پروژه استفاده شد، امکان تنظیم `baseUrl` را دارد. بنابراین endpoint زیر در این آزمایش مستقیماً مورد استفاده قرار گرفت:

```text
https://127.0.0.1:27124
```

برای این مسیر نیازی به TLS proxy یا patch کردن سورس bridge نبود.

این جزئیات در مستندات پروژه ثبت شده‌اند تا مشخص باشد هر بخش دقیقاً بر چه شواهدی متکی است.

## همه‌چیز هم موفق نبود

یکی از بخش‌های مهم این پروژه اتفاقاً یک شکست بود.

هنگام خواندن کامل یک Research Card بزرگ در قالب Markdown، درخواست با این خطا مواجه شد:

```text
HTTP 500
errorCode: 50000
```

علت این خطا را مشخص نکردم.

این تصمیم عمدی بود. وقتی علت یک خطا را آزمایش نکرده‌ایم، نباید برای آن یک دلیل قطعی بسازیم.

بنابراین این مورد در پروژه به‌عنوان **FAILED** ثبت شده است و علت آن همچنان **NOT ESTABLISHED** است.

## چه چیزهایی هنوز تأیید نشده‌اند؟

در نسخهٔ `v1.0.0` چند مورد همچنان باز هستند:

- احراز هویت و session واقعی Claude Code
- پایداری Claude Code در اجرای طولانی
- اتصال کامل Claude Code به Obsidian
- عملیات نوشتن، ویرایش و حذف در Obsidian
- audio capture
- سازگاری automatic update
- سازگاری کامل built-in pluginها
- بررسی کامل وابستگی‌های native از نظر instructionهای CPU

این موارد را عمداً در مستندات پروژه جدا کرده‌ام تا بین «آزمایش نشده» و «کار نمی‌کند» تفاوت وجود داشته باشد.

## این پروژه دقیقاً چه چیزی را نشان می‌دهد؟

این پروژه نمی‌گوید:

> Claude Code روی تمام پردازنده‌های بدون AVX و AVX2 اجرا می‌شود.

چنین نتیجه‌ای از یک سیستم آزمایشی به دست نمی‌آید.

نتیجهٔ دقیق‌تر این است:

> در محیط آزمایش‌شده، با Intel Core 2 Duo E8400 و Windows 10، توانستم Claude Code نسخهٔ ۲.۱.۲۷۰ را با `cc2js` به یک bundle قابل اجرای Node.js تبدیل کنم و اجرای CLI و MCP پایه را تأیید کنم.

همچنین دربارهٔ Obsidian:

> مسیر MCP و REST مربوط به Obsidian به‌صورت مستقل آزمایش شد و چند عملیات خواندن با موفقیت انجام شد، اما workflow کامل Claude Code → Obsidian در این نسخه تأیید نشده است.

این تفاوت برای من مهم است.

## چرا این پروژه را منتشر کردم؟

هدف فقط پیدا کردن یک workaround نبود.

می‌خواستم نتیجه‌ای که به دست می‌آورم قابل بررسی باشد و مشخص باشد کدام قسمت را واقعاً آزمایش کرده‌ام، کدام قسمت هنوز باز است و کجا با شکست مواجه شده‌ام.

برای همین repository شامل مستندات مربوط به محیط آزمایش، روش تبدیل، تست‌ها، معماری Obsidian، نسخهٔ ابزارها و محدودیت‌های شناخته‌شده است.

نسخهٔ `v1.0.0` هم بعد از یک audit نهایی منتشر شد و به‌عنوان **Evidence Freeze** پروژه ثبت شده است.

اگر علت شکست را نمی‌دانیم، نباید برای آن علت بسازیم.
